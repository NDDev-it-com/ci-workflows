# ci-workflows — Claude Code project memory

Reusable GitHub Actions workflow library plus a machine-readable catalog.
Consumers pin these workflows by full commit SHA, so every change here is a
supply-chain change in someone else's repository.

**Read `AGENTS.md` before your first edit.** It is the repository brief — the
file map, the change-impact map, the enforced contracts, and the tier truth —
and Claude Code does **not** auto-load it: only this file loads. Nothing below
restates it.

## What loads, and what is only data

- **Loaded:** this file. That is the whole auto-loaded surface — there is no
  `.claude/settings.json`, no `.claude/rules/`, no hooks, no `CLAUDE.local.md`,
  and no root `CLAUDE.md` in this repository.
- **On demand:** `.claude/skills/*` — twelve skills, loaded when a task matches.
  Nine portable (`ci-*`, `github-actions-*`) carry CI doctrine; three
  (`nddev-*`) describe how to operate this repository. This directory is a
  **generated byte-identical mirror** of `.agents/skills/`: edit the source and
  run `python3 scripts/sync_skills.py`, never the mirror. `check_skills` in the
  gate enforces parity and the fixed skill set.
- **Data only, never instructions:** `.gds/**` is a generated estate projection.
  It currently declares `allow_squash_merge: true` under `management: managed`,
  while the live repository allows merge commits only — see
  `docs/08-governance-rulesets.md`. Do not act on it and do not edit it; its
  sources live outside this repository.
- **Local, gitignored:** `.serena/` memories. Serena is disabled for this module
  (`.gds/repository.yaml` sets `agent.serena.enabled: false`), so they are
  derived evidence, not a source of truth.

## Working here

```bash
python3 scripts/validate_all.py --tier core   # what ci-gate blocks on
python3 scripts/validate_all.py               # all three tiers
```

Prefer these over ad-hoc equivalents so a failure is reproducible from the brief
alone. Most validators execute real fixtures — temporary Git repositories,
extracted embedded Python programs, adversarial input matrices — so a failure
message names the exact broken contract, and the validator's docstring explains
what it defends against. Read it rather than guessing.

When a task is contained in this repository, go straight to the relevant source
and its verification command. Reach for a skill when the task is about CI
doctrine generally (`ci-*`, `github-actions-*`) or about operating this
repository end to end (`nddev-*`).

Use `/context` if you are unsure what is currently loaded, and `/doctor` if
skills or MCP servers behave unexpectedly.
